# ADR 0014：独立配置来源、工作目录与同目录多服务

- 状态：已接受
- 日期：2026-09-09
- 部分取代：ADR 0006、0011、0013 中的固定配置位置和目录唯一约束

## 决策

`enable`、`edit` 接受 `-f/--file PATH`，任意文件名均按 JSON5 解析。显式选择不搜索其他
配置、不发出弃用警告、不回退。自动发现保留 ADR 0013 的文件优先级。`edit -f` 创建缺失
模板及父目录，已有源文本不改写。其他管理命令继续按名称或当前工作目录定位服务。

`enable`、`run` 接受 `--workdir DIR`，配置增加可选 `cwd`。持久服务按 CLI 覆盖、配置
`cwd`、配置文件所在目录选择工作目录。CLI 相对路径基于调用目录，配置相对路径基于
配置文件所在目录。`enable` 未传 `-f` 时，从指定工作目录或调用目录发现配置。
旧 `.env.served` 仍在配置旁读取。临时服务忽略所有配置，默认目录是调用目录，默认名称
取最终工作目录名。

普通启用保留目录软链接，目标始终是配置发现目录。显式指定文件或工作目录时，注册表
`enabled/<name>` 保存权限为 `0600` 的 JSON 记录：`version: 1`、`source`（`kind` 为
`directory` 或 `file`，`path` 为绝对路径）和可空的 `workdir` 覆盖值。记录通过临时文件
和原子无覆盖发布写入。旧链接按目录来源读取，不迁移。启动设置失败时回滚新记录。

restart 和恢复按原来源加载，工作目录变化不改变配置来源。CLI 覆盖持续生效，更换或
清除它需要 disable 后重新 enable；不回写配置。最终目录必须有效，重启验证失败时
保留旧进程。显式文件路径规范化父目录并保留文件名，以便重新读取编辑器替换后的文件。

名称仍全局唯一，工作目录可以共用，包括 enabled 和 temporary 服务。目录匹配多个
服务时拒绝操作，按名称排序列出候选。名称操作只作用于指定服务。

manager 协议升级至 v8，Enable 新增 `file`、`workdir`，ServiceInfo 新增可空的
`config_file`，`directory` 保持最终工作目录含义。来源信息和原始 `cwd` 不进入 runner
wire 或运行定义比较，runner v1 保持兼容。客户端与 manager 需同步升级。

## 结果与验证

配置文件可集中存放，API 与 worker 可使用独立配置并共用项目目录。目录操作不再保证
唯一，需要在有歧义时指定名称。每个配置文件仍只定义一个服务。

自动化测试覆盖相对路径、配置优先级、模板编辑、PTY 与管道 cwd、dotenv 位置、同目录
定位、无效重启、名称冲突、旧链接、新注册记录、崩溃恢复、handoff 和正常恢复。
