# ADR 0006：JSON5 源配置与外部编辑

- 状态：已接受
- 日期：2026-07-31

## 背景

配置编辑器已经变成第二套面向表单的 UI。它重复了配置 schema，让多行 shell 命令更难检查，
也让简单的 `Esc` 转义行为变得不直观。环境覆盖值还单独放在固定文件中，虽然它们本质上
属于服务定义。

管理器需要一种可以自我说明的可编辑源格式，不依赖额外文档；已有安装仍必须继续读取
`.env.served` 文件。

## 决策

- `.served.json` 继续作为固定的服务定义文件名，但按 JSON5 解析。接受注释、不加引号的
  键、单引号字符串和尾逗号。
- 新执行 `served edit` 时，如果 `.served.json` 不存在，就从带注释的模板创建。模板说明
  所有支持的字段，包括重启策略、TTY 行为、PTY 尺寸同步、日志持久化和字面量环境值。
- 提供 `-e/--editor COMMAND` 时，`served edit` 优先使用它；否则使用 `$EDITOR`。编辑器
  命令可以包含参数；配置路径作为一个安全引用的最后参数追加。`--path` 创建缺失模板并
  只打印绝对路径。`--path` 与 `--editor` 冲突。
- `served edit` 永远不重写、重新格式化或用模板合并已有配置源。格式错误的文件仍保留，
  供用户在外部编辑器中修复。
- JSON5 `env` 对象包含字面量字符串覆盖值。环境优先级为管理器启动环境、旧版
  `.env.served` dotenv 值、JSON5 `env` 值。项目 `.env` 与此无关，也永远不会读取。
- 新模板不创建 `.env.served`；这个固定文件仍作为旧服务目录的只读兼容输入。

## 结果

服务 schema 只有一个源文件，注释也会随服务一起保存。TUI 不再需要专用的 schema 文本
编辑器或 popup 状态。用户可以继续使用现有编辑器流程，包括编辑器参数和无界面的路径查询。
旧版环境文件仍然兼容；方便时，新配置应把值迁移到 JSON5 `env` 对象中。
